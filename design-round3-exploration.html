API Test Studio · round three · 12 Aug 2026

A test case is a saved request, not a prerequisite

Today the request playground is a modal bound to a selected case, and a second, weaker builder sits in the right-hand pane. This round collapses both into one inline builder, puts an unsaved scratch request at the centre of the workspace, and demotes “save as test case” to what it should always have been: an optional act you perform on a request that already works.

§0 — what the code says before I draw anything

Four findings from the source, three of which are shipping bugs

I grepped before I sketched. Two of these change the design; two are defects you can fix in an afternoon regardless of whether any of this gets built.

finding 1 · design

currentCase() is the chokepoint

46 call sites. Every exec* function, renderTry, renderResp and renderExecBody reach for it. Nothing can be edited that is not a case, because nothing knows how to read anything else.

But sendRequest(caseOverride) already takes any case-shaped object. The send path does not need to change at all — only what feeds it.

finding 2 · bug

Four CSS tokens are used but never defined

--panel (11 uses), --warn (7), --line (5), --warn-soft (1). Nineteen of those uses have no fallback, so the declaration is invalid at computed-value time and drops.

Visible effect: in the Preview tab and the execute modal, “⚠ Not found in loaded spec” renders as plain body-coloured text, and every background:var(--panel) code surface is transparent. border:1px solid var(--line) draws no border.

finding 3 · bug

The response viewer reports two numbers it cannot know

Size is (run.body||"").length — that is UTF-16 code units, not bytes. A response with any multi-byte character is mis-sized. Use new Blob([text]).size.

And lastRun.body is text.slice(0,20000). A larger response is silently truncated with no indication in the UI. Both are fixed in §1.5.

finding 4 · bug

The request tabs are not reachable by keyboard

.tp-tab is a bare <div> with data-tab and a delegated click handler — no tabindex, no role, no aria-selected. Params, Headers, Body and Preview are mouse-only. The whole app has exactly one keyboard shortcut, ⌘↵ at line 4680.

the shape of the fix

One rename carries most of the change

currentCase() → activeRequest(), returning state.draft when nothing is selected and the selected case when something is. The 46 call sites keep working because both objects have the same shape. Everything in §1 is downstream of that one function.

What I am not touching. Modules and their service × env base URLs, the Run Report and its failure grouping, the 6-lane pool with timing/load cases pinned serial, capture chaining, CSV/Sheet import, CSV export, spec-driven sync and coverage, and the spec-vs-response check. Round two shipped those. Every screen below is additive or a straight substitution.

1.1 · The scratch request, in state

One object, the same shape as a case, minus the things that make a case a case: no id, no scenario, no expected, no status. That is the entire model change.

// state.draft — the scratch request. Persisted with the module so a reload
// does not lose what you were poking at. Never appears in state.cases.
state.draft = {
  method:"GET", path:"/templates",
  query:[{key:"page",value:"1",enabled:true}, …],
  headers:[], pathVars:{}, body:"", bodyMode:"json",
  ephemeral:true,      // ← the only new field
  lastRun:{…}
};

// replaces currentCase() at all 46 call sites
function activeRequest(){
  return state.selectedId ? moduleCaseById(state.selectedId) : (state.draft ||= newDraft());
}

// sendRequest() needs exactly one guard added, at line 2848:
const verdict = c.ephemeral ? null            // a scratch send has no verdict…
  : (error ? "fail" : expectedIncludes(status) ? "pass" : "fail");
if (!c.ephemeral && (c.status==="pending" || !c.status)) c.status = verdict;
Why this is cheap. buildUrl, buildHeaders, buildBody, buildCurl, caseTimeoutMs, applyCaptures and checkResponseAgainstSpec all take a case-shaped object and never look at id. The scratch request flows through the existing send path untouched. Without the ephemeral guard, an unsaved GET that returns 200 would be recorded as a “pass”, which is the one thing that would poison the Run Report.
1.2 · Loading an endpoint does not create anything

Clicking GET /templates in the explorer calls syncCaseWithSpec() — the function that already fills query, path vars and body from the spec — against state.draft instead of against a case. Path params, required-flags, enums, defaults and the sample body arrive for free.

If the scratch request has unsaved edits, loading a different endpoint over it shows an inline undo affordance in the crumb strip — “Replaced POST /submissions/init · Undo” — for eight seconds. No modal. The previous scratch is one entry deep in History anyway (§4), so this is a convenience, not a safety net.

1.5 · The response pane, in detail
  • Status strip. Code + reason from the existing httpStatusText(), duration from the existing performance.now() pair, size from new Blob([text]).size, and the spec verdict pill from checkResponseAgainstSpec(). All four already exist; only the size is wrong today.
  • Body / Raw. Body is pretty-printed and highlighted; Raw is the untouched bytes as returned, which is the only way to see whitespace, a BOM, or an HTML error page a proxy substituted. Non-JSON content types skip straight to Raw with a note naming the received Content-Type.
  • Truncation is stated. When text.length > 20000 the pane ends with a bar: “Showing the first 20 000 characters of 84 219. Download to see all.” — and Download streams the full response, which means lastRun must keep the full body in memory for the current request even though the persisted copy stays clipped.
  • Headers tab lists what the browser will actually give us, and says so: “7 of the response’s headers are readable. Cross-origin responses expose only CORS-safelisted headers unless the API sets Access-Control-Expose-Headers.” Without that line, a QA engineer checking TC_004 Response headers correct will report a missing HSTS header that is actually present on the wire.
  • Timeline tab is honest about what a browser can measure: request sent → response complete, wall clock, with a greyed “time to first byte — not available cross-origin”. If the API sets Timing-Allow-Origin, the pane fills in from the Resource Timing entry.
  • Search (⌘F inside the pane) filters and highlights matching lines, keeping enclosing braces for context — the yellow line 6 in Fig 1 is the highlight style.

2.1 · What securitySchemes should drive

Today auth is a single topbar token that is always sent as Authorization: Bearer <token>. That is right for { type:"http", scheme:"bearer" } and wrong for everything else. The import step should read the scheme and configure the auth control accordingly:

Scheme in the specAuth control rendersSent as
http · bearerone token field Authorization: Bearer …
http · basicuser + password fields Authorization: Basic btoa(u:p)
apiKey · in: headerone field, labelled with the scheme’s name<name>: …
apiKey · in: queryone field ?<name>=…
apiKey · in: cookiea field plus a warning not possible Cookie is a forbidden header; fetch cannot set it. Offer the cURL copy instead.
oauth2 / openIdConnecta token field plus the discovered tokenUrlA full auth-code flow needs a redirect URI and a client secret. Client-credentials can be done from the browser if the token endpoint sends CORS headers; otherwise paste a token.
two or more schemesa scheme picker in the auth popover, remembering one choice per modulePer-operation security overrides the root default, and the builder’s Auth tab shows which scheme this operation requires.

For the Swivl spec there is exactly one scheme and it is bearer, so the visible result is that the existing auth chip gets a label — bearerAuth instead of a bare dot — and an “applies to all 22 operations” line. The generality matters for the next spec someone connects.

§4 — history

History records sends. The Run Report records verdicts. Neither repeats the other.

The distinction that keeps them from becoming the same list: a History entry has no verdict. It is a receipt for something you did. A Run Report row is a judgement about whether a case passed. Exploration produces the first and never the second.

History · new

“What did I just send?”

Per module, ring buffer of 50, persisted in localStorage alongside state.runs. Every send from the builder writes one entry: method, resolved path, status, duration, size, timestamp, and a full snapshot of the request configuration.

Reopening an entry loads that snapshot into the scratch request. It does not restore the response body — bodies would blow the 5 MB quota — but it does re-run on demand.

Run Report · exists

“What is broken?”

Unchanged from round two: runs numbered, failures grouped by cause, inline expansion, run-to-run delta. Its unit is the run, not the request.

The anti-duplication rule: Run All writes exactly one History entry — “Run #7 · 102 requests · 4 failed” — which links into the report. Not 102 entries. History stays a human-scale list of things a human did.

9.1 · What cannot be done client-side, with no build step
WantedVerdictWhat I would do instead
YAML spec import needs a parser There is no JSON.parse for YAML. Two honest options: vendor js-yaml.min.js (~40 KB) inline as a marked block — legitimate, still no build step, +15 % file size — or ship a ~120-line subset parser for block mappings, sequences and scalars that covers most OpenAPI files and fails loudly with “this YAML uses anchors, which this parser does not support — paste JSON instead”. I would vendor js-yaml; a subset parser that silently mis-reads a spec is worse than no YAML at all.
Reading all response headers impossible Cross-origin, fetch exposes only the CORS-safelisted six unless the API sends Access-Control-Expose-Headers. TC_004 (“Content-Type + CORS + HSTS present”) cannot be fully verified in a browser. The Headers tab must say so rather than imply the headers are absent.
Setting Origin, Cookie, Host, Referer impossible Forbidden request headers; the browser drops them silently. That kills TC_018 and TC_019 (CORS preflight from an allowed / disallowed origin) and any cookie-auth scheme. These cases should be marked Blocked — not runnable in a browser with a one-click cURL copy, not left to fail confusingly.
Time to first byte mostly impossible Resource Timing zeroes its detail cross-origin unless the server sends Timing-Allow-Origin. The Timeline tab shows total wall clock and greys the rest, labelled.
True concurrency beyond ~6 browser cap Chrome allows 6 connections per origin over HTTP/1.1, which is exactly why round two chose 6 lanes. Raising the lane count past 6 queues in the network stack and the timings become meaningless. Keep the cap and say why in the tooltip.
Streaming POST /templates/generate possible today It is an SSE stream, and await resp.text() at line 2831 buffers until the stream closes — for a long generation the UI simply hangs. Reading resp.body.getReader() and appending chunks is ~30 lines and gives the response pane a live streaming mode. Worth doing; it is one of the 22 operations.
Sequencing I would actually follow. (1) The design-system commit — four missing tokens, three contrast fixes, focus ring. Nothing visual changes except that things stop being invisible. (2) currentCase() → activeRequest() plus the ephemeral guard, with the UI untouched — a pure refactor you can verify by running the existing 102 cases and getting the same report. (3) The three-pane layout and the deletion of the Try pane. (4) Everything else, in any order. Steps 1 and 2 are independently shippable and carry no design risk, which matters for a file with no test suite.

Round three of three. Round one chose the run-report direction; round two added modules, concurrency and chaining; this round makes the request the primitive and the test case the by-product.
